# 다독임 변경 로그

## 기록 규칙

- 실제로 수행한 문서, 코드, 설정, 데이터 구조 변경만 기록한다.
- 계획했지만 수행하지 않은 작업은 완료된 변경처럼 기록하지 않는다.
- 각 항목에는 날짜, 변경 대상, 변경 내용, 변경 이유, 검증 결과를 남긴다.
- 제품 또는 기술을 선택한 이유는 의사결정 로그에 기록하고 이 문서에서는 해당 결정 번호를 연결한다.

## CHG-012. 비관적 요구사항 독립 검수와 상태 교정

- 날짜: 2026-09-01
- 변경 대상: `AGENTS.md`, `docs/README.md`, `docs/requirements.md`, `docs/decision-log.md`, `docs/development-workflow.md`, `docs/change-log.md`
- 발견한 문제:
  - 사용자 미확정 타이머, 플랫폼, 입력·저장 방식과 통합 MVP 범위가 `필수`, `포함`, `완료 조건`처럼 표현되어 있었다.
  - `C → B → A` 순서와 세 기능 전체를 첫 MVP 완료 조건으로 둔 내용이 충돌했다.
  - 모델 변경 절차는 DEC-016에서 제안인데 개발 가이드 본문은 적용 중인 규칙처럼 읽혔다.
  - 사용자가 요청한 시장 조사가 미완료 작업으로 추적되지 않았다.
  - 확인 필요 목록에 확정된 프로젝트 이름이 남아 있었다.
- 교정:
  - 사용자 확정, 구체화 초안, 제안을 관련 절 가까이에 표시하고 미확정 내용을 구현 기준에서 분리했다.
  - C의 첫 구현과 통합 MVP 후보를 분리하고, 기존 완료 조건은 통합 MVP 초안으로 낮췄다.
  - 모델 변경 절차를 미확정 제안으로 명시하고 시장 조사를 `요청됨·미수행`으로 추가했다.
  - 과거 DEC의 해소된 미정 상태에는 후속 결정 연결을 추가했다.
- 관련 결정: DEC-004, DEC-010, DEC-014, DEC-015, DEC-016
- 검증: 상태 표기 검색, 중복·충돌 재검사, Markdown 공백 검사와 변경 파일 존재 확인을 수행했다.

  - C·B·A·공통 제품·기술·비기능·시장 검증의 미확정 사항에 ID를 붙여 단일 체크리스트로 정리했다.
  - 기존의 일부 항목만 담은 중복 목록을 단일 관리 위치 안내로 바꿨다.
  - 항목 결정 시 DEC와 체크 상태를 함께 갱신하고, 엄격 검수 승인 전에는 완성으로 표시하지 않도록 작업 지침을 보강했다.

- 상태 영향: 새로운 제품 요구사항을 확정하지 않았다. 기존 확정·제안·미정의 의미를 유지한 채 가시성만 높였다.
- 검증: 대시보드와 ID별 체크리스트, DEC-023, 작업 지침의 연결 및 미확정 제안의 상태 보존을 확인했다.
