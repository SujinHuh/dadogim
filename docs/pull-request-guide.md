# 다독임 PR 작성 가이드

## 목적

모든 PR에서 변경 내용뿐 아니라 변경 이유, 검증 결과, 제품 문서 연결과 개인정보 영향을 같은 형식으로 확인한다. GitHub PR 작성 화면에서는 [공통 PR 템플릿](../.github/pull_request_template.md)이 자동으로 열린다.

## 작성 원칙

1. PR 제목은 `영어 type: 한국어 제목` 형식으로 작성한다. type은 템플릿의 8개 중 주된 변경 목적 하나만 소문자로 선택하고 scope는 사용하지 않는다.
2. 본문은 한국어로 작성하며 코드 식별자, 명령과 파일명은 원문을 유지할 수 있다.
3. 하나의 PR에는 사용자가 한 번에 이해하고 검증할 수 있는 목적 하나만 담는다. 기능, 대규모 리팩토링, 무관한 포맷 변경을 섞지 않는다.
4. 변경 내용 요약에는 파일 목록만 쓰지 않고 사용자 동작 또는 문서 기준에서 달라진 점을 적는다.
5. 실행한 검증만 체크한다. 실행하지 못한 테스트·타입 검사·린트·빌드는 빈 체크 상태로 두고 이유를 적는다.
6. 제품 동작이나 결정에 영향을 주면 관련 `REQ-*`, `DEC-*`, `CHG-*`를 연결한다. 관련 항목이 없으면 `없음`이라고 쓴다.
7. 실제 일기·확언·음성, API 키, 인증정보와 개인 식별 정보가 포함되지 않았는지 확인한다.
8. 로컬 기록 형식이나 저장 동작을 바꾸면 호환성과 마이그레이션 영향을 적는다.
9. 아직 검토가 필요한 작업은 Draft로, 완료 조건과 검증을 충족한 작업은 병합 가능한 PR로 표시한다.
10. 실패한 테스트를 통과시키기 위한 근거 없는 assertion 약화·snapshot 갱신·skip·테스트 전용 프로덕션 분기를 허용하지 않는다.
11. `main`에 직접 푸시하거나 PR을 자동 병합하지 않는다. 병합은 사용자가 diff와 검증 결과를 확인한 뒤 결정한다.

## PR 크기 판단

줄 수를 기계적으로 제한하기보다 리뷰 목적과 검증 단위로 판단한다. 다음 질문 중 하나라도 `아니요`라면 PR을 더 나눈다.

- PR 제목 한 문장으로 변경 목적을 정확히 설명할 수 있는가?
- 요구사항 또는 결정 하나와 직접 연결되는가?
- 변경 이유와 영향 범위를 3~5개 항목 안에서 요약할 수 있는가?
- 관련 검증을 한 묶음으로 실행하고 결과를 판단할 수 있는가?
- 사용자가 무관한 코드나 문서를 건너뛰지 않고 전체 diff를 검토할 수 있는가?

문서 초기 등록처럼 기존 파일을 올리는 작업도 운영 지침, 요구사항, 시장 조사처럼 검토 목적별로 나눈다.

## PR 제목 type

| type | 사용하는 경우 | 제목 예시 |
|---|---|---|
| `feat` | 새로운 사용자 기능이나 동작 추가 | `feat: 멍 때리기 소리 추천 흐름 구현` |
| `fix` | 잘못된 동작이나 오류 수정 | `fix: 재생 종료 후 타이머 상태 수정` |
| `refactor` | 동작을 바꾸지 않는 코드 구조 개선 | `refactor: 오디오 상태 책임 분리` |
| `test` | 테스트 추가·수정이 주된 목적 | `test: 재생 중단 복구 테스트 보강` |
| `docs` | 문서만 변경 | `docs: C 기능 완료 조건 정리` |
| `build` | 빌드 설정·패키지·의존성 변경 | `build: Expo 오디오 의존성 추가` |
| `ci` | GitHub Actions 등 CI 자동화 변경 | `ci: PR 자동 검증 워크플로 추가` |
| `chore` | 위 유형에 속하지 않는 저장소 유지보수 | `chore: PR 템플릿 설정` |

- 제목에는 type을 정확히 하나만 사용한다.
- 작업 중 PR은 GitHub Draft 상태를 사용하고 제목에 `draft:` 또는 `[Draft]`를 붙이지 않는다.
- scope와 `BREAKING CHANGE`는 현재 기본 형식에 포함하지 않으며 필요성이 생기면 별도 결정한다.

## 섹션별 작성 기준

### 테스트 및 검증

명령과 실제 결과를 적는다. 문서만 변경한 경우 Markdown 구조·공백·링크와 비밀정보 포함 여부처럼 실제 수행한 검사를 기록한다. 실행하지 않은 항목을 성공으로 표시하지 않는다.

### 개인정보·보안·데이터 영향

민감정보 외부 전송, 비밀정보 추가, 로컬 기록 호환성과 마이그레이션 영향을 각각 확인한다. 영향이 없으면 `없음`이라고 명시한다.

### 추가 설명과 남은 위험

이번 PR에서 의도적으로 제외한 범위, 후속 PR, 알려진 한계와 재검토 조건을 적는다.

### 리뷰 요청

사용자가 집중해서 볼 파일·동작·결정과 아직 확인되지 않은 사항을 구체적으로 적는다.
