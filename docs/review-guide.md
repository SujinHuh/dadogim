# 다독임 깐깐한 관리자 검수 가이드

## 목적

자동 검사가 확인하지 못하는 요구사항 충족, 실제 동작, 회귀, 개인정보·데이터와 오디오 위험을 구현자와 독립된 관점에서 판단한다. PR 설명이나 체크박스가 아니라 요구사항, diff와 실행 증거를 대조한다.

## 역할 분리

| 역할 | 책임 |
| --- | --- |
| GitHub Action | PR 제목, 필수 섹션, 빈 템플릿 등 결정적으로 판정 가능한 형식 검사 |
| 깐깐한 관리자 검수자 | 요구사항 일치, 정확성, 회귀, 증거의 충분성과 위험 판단 |
| 사용자 | diff와 검수 결과를 확인하고 병합 여부 최종 결정 |

Action과 AI 리뷰는 테스트, 브랜치 보호와 사용자 승인을 대체하지 않는다.

## 검수 입력

검수자는 필요한 항목만 읽고, 다음 입력이 없으면 없다고 명시한다.

- 기준 브랜치와 검수할 head SHA
- PR 제목·본문과 전체 diff
- 관련 사용자 확정 `REQ-*`·`DEC-*` 및 인수 조건
- 관련 `CHG-*`와 실제 변경 파일
- CI, 로컬 명령과 실제 기기 검증 결과

## 검수 순서

1. Git root, 기준 브랜치, head SHA와 diff 범위를 확인한다.
2. PR 목적 하나와 관련 확정 요구사항·결정을 연결한다.
3. PR 설명을 답으로 간주하지 않고 diff에서 실제 동작과 범위를 독립적으로 확인한다.
4. 정상·실패·중단·복구 흐름, 데이터 보존·삭제와 기존 동작 회귀를 확인한다.
5. 실행한 테스트·타입 검사·린트·빌드·실기기 결과가 같은 변경을 검증하는 증거인지 확인한다.
6. 문서와 로그가 실제 결정·변경 상태와 일치하는지 확인한다.
7. 발견 사항을 교정한 뒤 같은 기준과 최신 SHA로 재검수한다.

## 우선 반려 항목

다음 중 하나라도 확인되면 완료나 병합 가능 상태로 승인하지 않는다.

- 사용자가 확정하지 않은 제안을 요구사항처럼 구현함
- PR 목적 밖 기능, 대규모 리팩터링 또는 무관한 포맷 변경이 섞임
- 재현되는 오류, 데이터 손실·중복 또는 기존 기능 회귀가 남음
- 실제 일기·확언·음성, 인증정보나 개인 식별 정보가 노출됨
- 전화·알람·이어폰 해제·화면 잠금 등 오디오 생명주기 위험을 필요한 환경에서 검증하지 않음
- 실행하지 않은 검증을 성공으로 표시하거나 다른 SHA의 결과를 사용함
- 테스트 통과를 위해 근거 없이 assertion·snapshot을 약화하거나 테스트를 skip함
- 요구사항, 결정, 변경 로그와 실제 diff가 충돌함

## 판정

- `승인`: 차단 항목이 없고 이번 범위의 필수 검증 증거가 모두 있다.
- `조건부 승인`: 알려진 오류는 없지만 사용자 조작, 외부 권리 확인, 실제 기기처럼 아직 충족되지 않은 조건이 있다. 조건이 해소되기 전에는 병합하지 않는다.
- `반려`: 요구사항 불일치, 실제 오류, 범위 초과, 필수 검증 누락 또는 증거 부족이 있다.

비차단 제안은 차단 항목과 분리한다. 취향이나 미래 개선만으로 현재 PR을 반려하지 않는다.

## 결과 형식

```md
판정: 승인 / 조건부 승인 / 반려
검수 범위: <base>...<head SHA>

차단 항목:
- 없음 또는 파일·위치·재현 조건·영향·안전한 수정 방향

확인한 증거:
- CI 작업명과 결과
- 실행 명령과 결과
- 실제 기기 환경과 결과

미검증 항목:
- 항목과 이유

비차단 제안:
- 없음 또는 후속 개선

재검수 조건:
- 수정 또는 추가 확인 내용
```

## 호출 시점

- 기능 요구사항 묶음 확정 직후
- 작은 구현과 관련 자동 검사가 끝난 직후
- 아키텍처·개인정보·사운드 권리·오디오 백그라운드 변경 전후
- PR을 Ready for review로 바꾸기 전과 병합 직전
- 배포 직전

행동에 영향 없는 저위험 문서 변경은 작업 묶음 종료 시 한 번 검수한다. 제품 행동·데이터·권한·배포가 바뀌면 즉시 검수한다.

## Codex GitHub 리뷰와의 관계

저장소 전체에 적용할 핵심 규칙은 루트 `AGENTS.md`의 `## Code Review Rules`에 짧게 둔다. 세부 검수는 이 문서를 따른다. GitHub 연결 후 `@codex review` 또는 자동 리뷰를 추가 검토로 사용할 수 있지만, 사용자 병합 판단을 대신하지 않는다.
